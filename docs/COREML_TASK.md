# 任务：用真正的 Core ML 神经风格迁移替换 Metal 着色器近似

用户指令（2026-10-29）：在现有 App 基础上，直接实现。用 Core ML 实现风格转换，替换掉现在的 Metal 着色器效果。不要先交 Plan 等确认——直接做完。中间决策由 Sunny（上级）已授权你按本文件与工程既有决策执行；只有触发下方「停止条件」才停下来写报告。

背景文档：`docs/POC_SPEC_OPENAI.md`（用户提供的需求稿，技术要求以它为准，尤其是画质标准与诚实性要求；其中「等用户确认」的流程条款已被用户本人取消）。

## 目标

把三个风格的实际效果实现从 Metal 着色器近似切换为真实的端侧神经网络推理（Core ML），优先并重点保证「手绘治愈风」。Metal 只保留为预览渲染/色彩空间/必要后处理的管线角色，不再承担风格效果本身。

验收目标（按优先级）：画质 > 视频稳定性 > 实时性能 > 工程复杂度。

## 模型

1. 手绘治愈风：AnimeGANv3 Hayao。
   - 先从**官方仓库**核实：权重下载位置、代码许可、权重许可、输入/输出尺寸与归一化要求，并把结论写进结果报告。已知前期结论（Phase 3 `docs/MODELS.md`）：权重为非商用免费使用、商用需作者邮件授权；本次用途 = 用户个人设备上的非商用 POC 测试。在官方 README/LICENSE 原文中找到支撑本用途的条款后再集成；找不到依据 → 触发停止条件 1，写报告，不许用第三方重传权重绕开。
   - 官方没有 Core ML 版则自行转换：用工程已有的 `scripts/convert_animegan.py` 为起点，独立 venv、固定版本（torch/coremltools 写明版本），转换后做数值抽查（同一输入下 PyTorch 与 Core ML 输出差异在合理范围），结果记入报告。
2. Q 版萌系、2.5D 动画风：寻找可合法取得、可转换的真实模型（如 AnimeGANv3 官方其他已发布权重，如 Shinkai 等，按视觉贴合度分配）。**某个槽位若确实没有可信模型，如实在报告中写明并给出可选方向，禁止拿着色器冒充 Core ML 效果。**
3. 模型二进制是 gitignore 对象（现有同步通道只传文本）。交付一个可在用户 Mac 上一键执行的脚本（下载官方权重 → 隔离环境转换 → 把 .mlpackage 放进工程正确位置），并在 `codemagic.yaml` 增加同样的 fetch+convert 步骤，使云端模拟器验证跑的也是真模型（在演示帧上）。

## 实现要求

- 复用已有 `CoreMLStyleRenderer` / `InferenceGovernor` / 风格槽位架构，最小侵入；不重构摄像头与录制模块，不改 UI 结构（仅允许为「模型状态」做最小可见区分）。
- **禁止静默降级**：模型缺失或加载/推理失败时，该风格必须呈现明确的不可用/错误状态，不得悄悄回退到旧着色器还显示为 AI 模式。旧着色器代码可保留在工程中，但不得作为该风格的实际效果路径（除非在报告中明确标注为未完成项）。
- 推理不得阻塞主线程；沿用最新帧/有界队列策略避免积压；模型只加载一次。
- 录制链路验证：保存的视频必须来自风格化后的帧（现有管线本就如此，接入模型后复核一遍并在报告中确认）。
- 性能如实记录：推理耗时（平均/P95）、在 512 与 384 两档的实际处理 FPS、所用计算单元配置，写入结果报告并注明测试环境（本机 Linux 无法测 iOS 性能时，写明「待 Codemagic 模拟器/真机验证」，不许编造数字，不许用重复旧帧伪造 FPS）。
- 保持现有全部功能与测试绿：账号、作品库、录制保存、UI 均不得回归；新增模型状态相关逻辑要有测试。

## 停止条件（触发任一即停下，在报告中写清证据与可选下一步）

1. 官方来源无法确认权重授权覆盖本 POC 用途。
2. 转换后输出与原模型明显不一致或异常。
3. 需要大改摄像头/录制架构才能接入。
4. 依赖冲突会破坏现有构建环境。
